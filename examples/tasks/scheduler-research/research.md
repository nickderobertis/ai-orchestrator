## What
Read the scheduler and report how it selects the next runnable node, in `docs/scheduler-notes.md`.

## Why
The next change to the scheduler needs one written account of the current selection rule, so its author does not rediscover it from the code under time pressure.

## Acceptance criteria
- The note names the selection rule and the code that implements it.
- Every claim is traced to a file and symbol in this checkout.
